界面Interface · 920 × 700

整个窗口就是取景器。你在预览里看到的那块，就是录下来的那块 —— 包括你选的区域。 一个圆键，一个读数，设置收在一层之后。参数不摆在脸上，因为录屏本来就只有一件事。

03

三个不那么显然的决定Engineering decisions

这个项目里真正花时间的不是写界面，是下面这三件事。每一条都是先验证、后写进代码的。

i

不用 JavaCV，直接调 FFmpeg 命令行

JavaCV 会往依赖里塞 200MB+ 原生库，而它封装的恰恰就是一条命令行。 直接 ProcessBuilder 调二进制：区域录制只是三个参数 -offset_x-offset_y-video_size， 出错时能逐行接住 FFmpeg 的 stderr 展示给用户，而且 jrec-core 的运行时依赖是零。

ii

停止录制发 q，不是 kill

MP4 的索引 moov 写在文件尾部，进程被强杀就写不进去，文件直接报废。 FFmpeg 接受 stdin 上的 q 来正常收尾。所以停止路径是： 写 q → 等 15 秒 → 仍不退出才降级为强制结束。 这条行为是先写了个最小程序验证 exit code 和产物完整性，才写进代码的。

iii

区域在采集端裁剪

gdigrab 支持只读一块矩形，编码器从头到尾只看到用户选的那块。 相比之下「录全屏再裁」要多解码一次全屏，纯属浪费。 macOS 的 avfoundation 没有这个能力，只能退回 crop 滤镜 —— 这也是 macOS 上区域录制更费 CPU 的原因。

05

跑起来Run

需要 JDK 17+ 和 Maven 3.8+。不需要预装 FFmpeg —— 首次启动若找不到，界面会提示并提供一键下载。

bash
# 构建并安装到本地仓库
$ mvn install -DskipTests

# 启动桌面端
$ cd jrec-desktop && mvn javafx:run
